## 回归机制与本轮修复

### 1. 退役先冻结原stream，再停止旧socket

此前先退役socket/更新代际，取消分支只本地释放reply登记。对已经显示“处理中”的消息，这能清掉本机状态，却没有finish把用户看到的stream关闭。

当前[编排层](<../src-tauri/src/wecom_orchestrator.rs>)与[通道层](<../src-tauri/src/wecom_channel.rs>)正在接入统一`orch.retire`：

1. 暂停ingress；新模型工作不再进入旧代际。
2. 快照已登记旧任务的reply target；在原socket和Bot仍持有原req_id时冻结中断final，已经冻结的最终答复不被覆盖。
3. 取消原request/preflight并invalidate旧代际，清理旧任务执行。
4. 在**共用2秒预算**内尝试向旧socket入队这些final，再等待flush barrier。
5. 记录`retirement/socket_drained`或`delivery_unavailable`，随后stop旧socket并完成后续切换。

`socket_drained`只表明本地socket writer的flush完成，不是平台ACK，更不是客户端展示/用户已读。2秒不是每帧2秒，也不是可靠送达保证；队列拥塞或连接已关闭会留下delivery_unavailable。正常final先冻结后，退役不产生替代正文。

### 2. 比较有效配置，区分无变化、热更新与冷变更

新增[有效配置快照](<../src-tauri/src/wecom_channel_config.rs>)：先解密并归一配置语义，再比较字段摘要；随机DPAPI密文变化不当作配置变化。快照只持有字段摘要；诊断只记`source`、`changedFields`、计数与代际，不记录凭据原值或配置摘要值。

- 无有效变化：`apply/noop`，保留活动回合与socket。
- 热更新：如模型/effort、显示或调度等由分类表认定的字段，记录`hot_update`，不因保存本身退休通道；后续模型配置生效与当前已在途调用分开看。
- 冷变更：启停、Bot凭据、引擎、权限、工作区、MCP、访问策略/配对、agent策略及SkyWalking源等，走受控退役。
- 手动restart与profile sync也走同一退役路径，并记录`source=restart/sync`；apply记录`source=apply`。

这是未来触发可追溯性增强，不反推16:34:03一定是哪种source。旧文档“每次保存都重连”或“先stop再收尾”的描述只代表前一实现，当前顺序以本节为准。

### 3. 完整短进度问句先路由，不启动新模型任务

新增[wecom_progress.rs](<../src-tauri/src/wecom_progress.rs>)及入口路由：去掉首尾空白/标点后，只识别完整短句“进度 / 查到哪了 / 还没好吗 / 还没好 / 好了吗 / 当前进度”。长句中的相似片段不被截走；**“任务状态”继续属于共享任务命令**。

通过既有策略和会话作用域判定后，状态短句在模型准入/会话等待之前回复内存状态，不新建模型任务。返回当前阶段、耗时、距最近活动时长与采集计数，或最近任务的结束原因；同会话有运行中任务和新排队项时优先展示running，排队数量另列。

进度状态的边界：

- 进程内最多256条，按精确会话作用域关联；不存日志/模型正文/工具参数。
- 已结束记录采用**结束后2小时TTL**，读取不续期；容量压力先回收最早结束项。活跃项不因2小时TTL被淘汰，容量全为活跃项时不抢占已有记录。
- 独立timer检查心跳，未出现可见正文时最多每30秒一条状态。工具活动更新“最近活动”，不推迟30秒节奏；状态询问也不续期或重置节奏。
- 普通正文一旦开始显示，自动状态心跳停止，避免覆盖正文；protected planning/报告协议不当作已显示正文。
- 首次terminal冻结，迟到活动/结束不覆盖；“ended/unknown”保留未知，不机械改成成功。

### 4. 同用户同Bot租约与有界发送

新增[BotLease](<../src-tauri/src/wecom_bot_lease.rs>)：按当前Windows用户目录与Bot ID摘要取得`share_mode(0)`文件句柄锁；文件不写凭据或owner PID。锁由存活句柄持有，空文件留存不等于仍被占用；释放连接后再释放租约。

**锁仅协调采用该机制的实例。旧安装版尚未采用锁，仍可能与新开发版冲突。** 所以这不是本次同Bot双连接的证明，也不是所有版本/机器之间的全局单连接保证。

[WS Outbox](<../src-tauri/src/wecom_ws.rs>)改为最多64项队列：同req_id/stream的待发progress可合并，遇final或flush边界停止跨界合并；final与其他命令不被progress覆盖，满队列等待空间而非无限增长。200ms pacing是本地保守节奏，不是平台官方速率契约。flush barrier报告writer侧完成/失败，不把writer关闭当成功。

平台回执当前记`platform_ack`、`code=final_frame_unknown`，只按req关联；同一个req可能用于progress和final，没有唯一frame标识时不把ACK归给最终帧。`enqueued`、`socket_written`、`socket_drained`、`platform_ack`与用户已读是不同层次。
